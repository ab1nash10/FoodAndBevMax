## Corrections to "what exists today"

- Tests exist already: vitest in all three services (`*.spec.ts`, `*.int.spec.ts` against
  `DATABASE_URL_TEST`), node's test runner via `tsx --test` in `@aahar/auth` and `@aahar/config`.
  No Jest setup was added (L0): a second runner would duplicate vitest.
- `AuditLoggerService` (console only) is provided in the three app modules but **called by nobody**.
  Every service already writes `audit_logs` through its own `AuditLogService.record(input, tx?)`
  (organization-service and user-service) or `AuthAuditLogService` (auth-service).
- Stock and money paths already write their audit row with the transaction client (`tx`), so
  rule 4 already held for every audited path; values were whole response objects, not diffs.
- Request ids exist: `correlationIdMiddleware` (x-request-id, echoed), `requestLoggingMiddleware`
  (JSON via console, failed/slow requests only), slow-query warnings (`query-log.ts`).
- organization-service already maps Prisma errors in `common/prisma-errors.ts`.
- The permission `AUDIT_LOG_VIEW` is already seeded (`prisma/seed.ts`) and gates the portal's
  `/reports/audit` page, which is an empty placeholder.

## Decisions

- **Commits held.** The working tree already carried ~1,000 lines of uncommitted user work
  (ERP GRNs, till guard, ~80 spec files) in the same files this work touches (`schema.prisma`,
  `global-exception.filter.ts`, `app.module.ts`, audit services). Committing per task would have
  swept that work into these commits, so nothing is committed; each task lists its files below.
- **Test runner:** kept vitest (services) and `tsx --test` (packages); no Jest.
- **Action names:** existing entity-prefixed actions (`GRN_POST`, `ITEM_CREATE`, `TRANSFER_DISPATCH`,
  …) are kept so old and new rows read the same; docs/logging.md maps them onto the catalogue.
  New events use catalogue names.
- **The dev OTP is no longer logged** (rule 1 has no exceptions); development signs in with 000000.
  `otp.service.spec.ts` updated: the code must never reach any log line, in any environment.
- **Access log on every request.** It used to log only failed/slow requests (a line per request cost
  ~12% CPU as JSON.stringify + console.info). pino writes asynchronously; if load tests show a cost,
  set `LOG_LEVEL=warn`, which drops success lines before they are built.
- **Audit hospital from context** only when it is one of the caller's assigned hospitals: a hand-typed
  id from a Super Admin would fail the FK and roll back the business transaction.
- **Audit phones are not masked** (they are business data in those tables already, and masking would
  lose a mobile change's before/after); logs mask them. Security events mask phones explicitly.
- **Columns are TEXT**, not uuid/enum (location_id, request_id, source): a malformed value must never
  fail the stock transaction that writes the row.
- **Transfer acknowledgements are recorded on the transfer** (entity `transfers`, the acknowledgement id in the value), so a transfer's history shows how it was received. Older rows sit on `transfer_acknowledgements`.
- **Background (not transactional) audit** for kiosk orders, online payments, ERP order pushes and order status: none of those writes runs in a transaction today, and rule 4's list does not name them.
- **Audit API lives in organization-service**: it already has the hospital-scope guard/interceptor and most audited entities; user/auth rows are read from the same table.
- **Permission `AUDIT_LOG_VIEW`** (already seeded, already gating the portal page) instead of a new `audit.view`: no permission or role data changes. Export uses the same permission and is itself audited.
- **Scoped users see only their hospitals' rows.** Rows without a hospital (sign-ins, shared masters such as items and categories) are visible to unrestricted users (Super Admin) only.
- **Events without a record** (failed sign-in by an unknown user) use entity id
  `00000000-0000-0000-0000-000000000000` (`NO_ENTITY_ID`); entity_id stays NOT NULL uuid (additive rule).
